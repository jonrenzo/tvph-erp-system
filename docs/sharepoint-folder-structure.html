SharePoint folder structure — vendor docs plus POs

Plan only. Covers where to put vendor accreditation files, generated POs, and signed POs in one SharePoint site so staff can browse without the app. Under 100MB per file, chunked upload at 4MB.

Site: sites/TVPH-ERP — Library: Shared Documents — Provider: lib/storage/sharepoint.ts

Current S3 paths today

Vendor docs go to vendor-documents/vendors/{vendorId}/{docType}/{file} app/dashboard/vendors/actions.ts:139. Signed POs go to po-artifacts/po/{poId}/signed-{ts}.pdf app/portal/actions.ts:194. Legacy POs go to po-artifacts/legacy/{id}/{poNumber}.pdf app/dashboard/purchase-orders/actions.ts:2010. Artifacts table tracks issued PDFs purchase_order_artifacts. Generated POs are rendered on fly at app/api/purchase-orders/[id]/pdf/route.ts:84 and not stored unless signed or legacy.

Proposed SharePoint structure — one site, two top folders

Keep ids in the path for uniqueness, but prefix with human labels so the library is searchable and sortable. Use SharePoint columns for filter, not deep naming tricks.

Shared Documents/ ├── 01_Vendor-Documents/ — maps to vendor-documents bucket │ ├── VEND-0012_Acme-Builders_a1b2/ — {vendorCode}_{slugName}_{shortId} │ │ ├── 01_Business-Permit/ │ │ │ ├── Business-Permit_20250824_0_original.pdf — {docType}_{timestamp}_{index}_{orig} │ │ └── — older uploads stay as versions, SharePoint also keeps version history │ ├── 02_BIR-2303/ │ ├── 03_SEC-Certificate/ │ ├── ... — 14 accreditation types from lib/vendors/document-types.ts │ └── 99_Custom_Pest-Control-Clearance/ — labelSlug from custom docs │ ├── VEND-0034_Jewelino-Tech_c3d4/ │ └── ... ├── 02_Purchase-Orders/ — maps to po-artifacts bucket │ ├── 2026/ — issued year from purchase_orders.issued_date │ │ ├── PO-2026-000041_VEND-0012/ — {poNumber}_{vendorCode}, link id {poId} │ │ │ ├── 01_Generated/ │ │ │ │ └── PO-2026-000041_generated.pdf — stored on first view or on issue │ │ │ ├── 02_Signed/ │ │ │ │ └── signed-20260824T101500Z.pdf — from po_signatures.signed_file_name │ │ │ └── 03_Artifacts/ │ │ │ ├── legacy_PO-2026-000041.pdf — legacy/{id}/{poNumber}.pdf │ │ │ └── completion-cert_20260820.pdf │ │ └── PO-2026-000042_VEND-0034/ │ └── 2025/ └── 03_Archive/ — optional, for retention moves

Why this layout

GoalHow folder gives it
Find vendor files without appBrowse 01_Vendor-Documents by vendor code folder. Search works because name contains code and slug.
Find PO without appBrowse 02_Purchase-Orders by year then PO number and vendor code.
Separate generated vs signed01_Generated is app snapshot. 02_Signed is vendor returned file. Auditors see both without mixing.
Keep ids for safetySuffix short id avoids collisions when two vendors share a name. Full id lives in DB.
Under 100MB handlingChunked 4MB upload works for both trees.

Vendor documents Flow after SharePoint

Upload from dashboard or portal

Provider path is 01_Vendor-Documents/VEND-0012.../01_Business-Permit/file.

Graph upload session for over 4MB

Under 4MB single PUT, else create session and send 4MB chunks. Portal anon upload uses app token.

Write DB rows same as today

Insert into vendor_document_files and vendor_document_file_versions with SharePoint webUrl plus item id.

Read via sharing link

POST /items/{id}/createLink per file, cache one hour like S3 signed URL today.

Add columns on this library: VendorCode, VendorId, DocType, ExpiryDate.

PO documents Flow after SharePoint

Generated PO snapshot

Render once via lib/pdf/renderPoDocument.ts and store to 01_Generated. Record in purchase_order_artifacts.

Signed PO from portal vendor

Upload to 02_Signed via Graph session. Insert po_signatures.signed_file_url as SharePoint webUrl.

Legacy import

Path legacy/{id}/ becomes 02_Purchase-Orders/{YYYY}/{PO}_{vendor}/03_Artifacts/legacy_...

Approval serves signed file

PDF route checks signed_doc_status and downloads from SharePoint item id.

PO columns: PONumber, POId, VendorCode, IssuedDate, Status, Project.

Performance for under 100MB

Folder depth does not affect speed. Graph finds items by id, not folder scan. An 80MB scan sends 20 chunks, shows 20 step progress, resume from last chunk if dropped. Direct to SharePoint from browser avoids Vercel limit.
