Server gets app token then uploads to SharePoint

Acquire token login.microsoftonline.com/{tenant}/oauth2/v2.0/token with Sites.ReadWrite.All. If file under 4MB: PUT /drives/{drive}/root:/vendors/{id}/{type}/{file}:/content. If over 4MB: create upload session and send chunks.

Store SharePoint item id and webUrl in database

Insert same rows in vendor_document_files but file_url is now https://tenant.sharepoint.com/sites/TVPH-ERP/.../file plus driveItem id. Version row still created, so rollback stays in your app.

↓

Read — create sharing link per file

Instead of createSignedUrls, call POST /drives/{drive}/items/{id}/createLink {type:"view", scope:"organization"} for each file needed on the page. Cache link until expiry. Batch is N calls, not one.

↓

Delete and rollback

Delete with DELETE /drives/{drive}/items/{id}. Rollback still flips file_url to older row — no need to restore SharePoint version history.

Extra work you accept: Azure app registration plus admin consent, token cache, chunked upload for over 4MB, and N sharing link calls instead of one batch.

Recommendation — plan only

SharePoint is viable and will not hurt performance if you scope it to vendor-documents first. Keep other buckets on Supabase until you see real Graph timing. I would pick this over a home server for your must keep versions rule. If IT denies admin consent, fall back to Supabase Pro — one click, same app. R2 sits in the middle if you want S3 like behavior without SharePoint ceremony.
